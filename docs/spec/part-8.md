Free-plan safety. Two limits matter: the per-invocation call count and, much more importantly, the free plan's 1,000 storage writes/deletes/lists PER DAY shared with uploads. Therefore every run is limited by an OpBudget object with two counters:
- MAINT_MAX_OPS = 400: the total number of binding calls (D1 statements/batches plus KV operations) in one run.
- MAINT_MAX_KV_MUTATIONS = 250: the number of KV deletes plus KV list pages in one run (these come out of the daily 1,000; the remaining 750 stay available for uploads). OpBudget exposes take(n) (D1 or other calls; counts toward the total only) and takeKv(n) (counts toward BOTH counters); each returns false when it would exceed a limit, and the step must then stop. Check the budget BEFORE every D1/KV call. Unfinished work simply continues on the next run. Use batching everywhere (json_each, DB.batch); KV deletes are one call per key, issued through storage.deleteMany. Each step is wrapped in its own try/catch so one failure never blocks the others (a StorageQuotaError ends the KV steps for this run and is logged as {"evt":"maintenance_quota"}). Steps in order:
1. Auto-expire (1 D1 op): read auto_expire_days; if > 0: UPDATE files SET deleted_at = ?1 WHERE deleted_at IS NULL AND pinned = 0 AND id < ?2 with ?2 = ulidFloor(now - days * 86400000) (the id comparison uses the primary-key index). Moving to Trash costs no KV operations.
2. Trash purge (up to 5 loops): each loop selects up to N ids, N = min(50, floor(remainingKvMutations / 2)) (stop the step when N is 0), with deleted_at IS NOT NULL AND deleted_at < now - trash_days * 86400000, returning id and thumb_size; delete their tag rows and file rows in one batch; then storage.deleteMany of f/<id> plus t/<id> only when thumb_size > 0. Stop when a loop finds nothing.
3. Orphan sweep (up to 4 list pages per run): resume from the cursor stored in settings key orphan_cursor (create the row lazily; INSERT OR REPLACE). storage.list(cursor, 1000) lists the whole namespace; keys that do not match ^(f|t)/[0-9A-HJKMNP-TV-Z]{26}$ are ignored and never deleted. Each listed key carries the metadata { size, at } written at upload; consider only objects whose at is older than 1 hour (a key with missing or invalid metadata counts as old). Look up the ids of the remaining objects with one json_each query per chunk of 500 ids (SELECT id, thumb_size FROM files WHERE id IN (SELECT value FROM json_each(?1))). Then apply planOrphanActions (below): delete from KV every object with no matching row; for a t/ object whose file row exists but has thumb_size = 0, instead set thumb_size to the object's size. Persist the new cursor (or clear it when the listing finishes).
